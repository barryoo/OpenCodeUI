# 登录与认证能力说明

## 1. 当前登录方式

当前支持：

1. GitHub OAuth 登录
2. 邮箱注册
3. 邮箱密码登录

## 2. 登录体验

### 2.1 未登录时

OpenCodeUI 打开后，如果当前没有登录，不会自动强跳 GitHub。

而是：

1. 弹出应用内登录提示弹窗
2. 用户可选择邮箱登录 / 邮箱注册 / GitHub 登录
3. 用户点击 GitHub 后才跳转 OAuth

### 2.2 登录成功后

登录成功后会建立 session cookie，并获取当前用户信息。

### 2.3 账号合并规则

如果 GitHub 返回邮箱，且系统中已存在同邮箱账号，则会自动合并到同一用户。

如果账号只有 GitHub 登录、尚未设置本地密码，则仍不能直接走邮箱密码登录。

## 3. 当前登录态如何使用

登录态主要影响：

1. Server Profiles
2. Items
3. Session Summaries
4. 事项与绑定关系

OpenCode 原始项目/会话请求不是靠 GitHub 登录鉴权，而是仍走 OpenCode 服务本身的连接配置。

## 4. 为什么要把登录态持久化

因为本次需求要求：

1. 用户数据隔离
2. 多端同步
3. 服务重启后不掉登录态

所以 session 不再是纯前端临时状态，也不是纯内存态，而是写入 SQLite。

## 5. 当前账号信息与数据隔离

当前登录用户会影响 thin server 侧的用户数据范围，包括：

1. Server Profiles
2. Items
3. Session Summaries
4. 事项与会话绑定关系

登出、未授权或切换账号时，前端会清理与当前用户绑定的本地状态，避免旧账号数据残留到新账号会话。

## 6. 当前 URL / 刷新恢复

登录不是唯一恢复条件。

当前刷新恢复还会依赖：

1. 当前会话上下文
2. 当前事项上下文

这样用户刷新后仍能回到对应的工作界面。
